# Official feeds can replace FRED; licences still gate the rest

The second sweep shows that Superfinancials can source almost every public-market and macro facet from **keyless or free-key official feeds that allow commercial reuse**. The earlier report treated several of these areas as gaps; this sweep found working endpoints for them. Daily government curves and overnight rates for the US, euro area, Germany, UK, Japan, Canada, Australia, Switzerland, Sweden and Norway come straight from Treasury, the NY Fed, the ECB, the Bundesbank, the BoE and their peers. That removes the platform's FRED dependency for rates. **SEC EDGAR doubles as a free corporate-events and new-funds feed**: Form 4, 8-K item codes, Form D pooled-fund filings at roughly 160 new funds a business day, and nightly XBRL company facts. Energy fundamentals now include GIE gas storage, ENTSOG flows, Elexon, EIA-930 and CFTC/ICE positioning. The five failing endpoints all have concrete, low-effort fixes:

- **SEC:** send a contact email in the User-Agent.
- **BLS:** same fix, a contact email in the User-Agent.
- **Eurostat:** move to the new `/o/calendars/` ICS URL.
- **OECD:** use smaller batched queries and add the COICOP-2018 flow.
- **World Bank:** parse the Pink Sheet XLSX instead of the dead `source=21` API.

Three corrections to the first report matter most:

- **African central banks are not API-less.** SARB documents a Web API, CBN's FX page exports CSV, and NGX sells an official EOD API for about ₦50,000 a year.
- **X costs less than estimated.** List timelines polled with `since_id` bring the cost to about **$100–200/month**, down from $150–600.
- **Some handles were wrong.** The verified handles are @ngxgrp and @nigerianstat, not @NGXGroup or @nbs_nigeria.

The hard limits from the first sweep still hold, and new ones were added:

- **Exchange end-of-day prices need a vendor's commercial licence everywhere.**
- **FINRA short data, Cboe, Nasdaq.com calendars, Open-Meteo, IEA free data, Global Fishing Watch and crypto free tiers are not for commercial display.**
- **Nigeria's NIBOR, OPR and secondary yields remain paid FMDQ products.**

**Nothing in this report was tested live.** Every research sandbox blocked or failed DNS for every provider host. The evidence is official-page search snippets plus maintained 2026 open-source code, some of it carrying dated live checks. Each endpoint must be smoke-tested from Vercel before use.

## Five failing endpoints have one-line causes and low-effort fixes

**SEC EDGAR's 403 is a User-Agent problem, not a block on GitHub or cloud IPs.** The SEC requires a declared bot header in the form `Sample Company Name AdminContact@<sample company domain>.com` and caps traffic at 10 requests per second ([SEC: Accessing EDGAR Data](https://www.sec.gov/os/accessing-edgar-data)). A UA that carries only a GitHub URL is treated as an "Undeclared Automated Tool". So is a malformed email such as `argus@local`, which "causes 403 on all EDGAR endpoints" ([argus edgar_fetch.py](https://github.com/ChickenTenders2/argus/blob/main/fetchers/edgar_fetch.py)). The same 403 also signals rate limiting. The 10/s budget counts per IP across www, data and efts.sec.gov, and an IP can stay limited until it has kept under the limit for 10 minutes ([DEV/odeeb](https://dev.to/odeeb/sec-edgar-rate-limit-and-user-agent-fair-access-rules-nki)). Another project runs live EDGAR checks from GitHub-hosted runners without trouble ([jay-session](https://github.com/jamesokpare/jay-session/blob/main/docs/BLOCKED_ON_DATA.md)). The fix has four parts: store `SEC_EDGAR_USER_AGENT="Superfinancials data-ops@<real-domain>"` as a secret; send `Accept-Encoding: gzip, deflate`; throttle to 2–5 req/s through one shared limiter; and back off at least 10 minutes on any 403. Daily index files such as `https://www.sec.gov/Archives/edgar/daily-index/2026/QTR4/form.20261022.idx` return 404 on weekends and holidays, so treat 404 as "no file", not as an error.

**BLS's 403 has the same root cause.** BLS "reserves the right to block robots that do not contain information that can be used to contact the owner" ([BLS terms](https://www.bls.gov/bls/blsterms.htm)). Two 2026 projects fetch `https://www.bls.gov/schedule/news_release/bls.ics` successfully with an email-shaped contact in the UA. One notes that BLS returns 403 unless the UA contains an email-format contact ([Code0716](https://github.com/Code0716/stock-price-repository/blob/main/config/economic_calendar.go); [Investedia](https://github.com/hellaynr1/Investedia/blob/main/calendar_official.py)). The evidence conflicts, though. Another project says BLS runs Akamai bot detection and wants a full browser UA ([bdecon](https://github.com/bdecon/bdecon.github.io/blob/master/scripts/update_calendar.py)). The plan is to send `Superfinancials-data-sync/1.0 (+https://<site>; contact: data-ops@<domain>)` with `Accept: text/calendar`, fetch once a day, and commit the last good ICS as a fallback. If cloud IPs are still refused, FRED's release-dates endpoint can serve the release calendar for live lookups only, because FRED's terms bar storing its content. Note that the BLS data API (`api.bls.gov`) answered 200 in a test where the website returned 403 ([C-NTO audit](https://github.com/0xSrk/C-NTO/blob/main/docs/AUDIT.md)).

**OECD's HTTP 500 is server-side, not a syntax error.** The flow `OECD.SDD.TPS,DSD_PRICES@DF_PRICES_ALL,1.0` and key `.M.N.CPI.PA._T.N.GY` match the 8-dimension order REF_AREA.FREQ.METHODOLOGY.MEASURE.UNIT_MEASURE.EXPENDITURE.ADJUSTMENT.TRANSFORMATION, and 2026 code uses both ([Jenner Analytics](https://docs.jenneranalytics.com/data-access/oecd/); [macro-pipeline](https://github.com/ECRSSREW22E/macro-pipeline/blob/main/docs/API_SOURCES.md)). A wrong code returns 400 or 404, not 500. **On 25 Sep 2026 OECD reported query timeouts caused by "abnormally high volumes of requests generated by automated activity"** ([OECD status](https://www.oecd.org/en/data/insights/data-explainers/2025/02/OECD-Data-Explorer-News.html)), and the 60-downloads-per-hour cap also covers Data Explorer CSVs. The new pattern has five steps:

1. Batch 8–10 countries per call, e.g. `…/DF_PRICES_ALL,1.0/USA+JPN+GBR+CAN+AUS+KOR+MEX+CHE.M.N.CPI.PA._T.N.GY?startPeriod=2021-01&format=csvfile`.
2. After the first backfill, query only a recent `startPeriod`.
3. Run calls serially, with a 1–2-minute backoff.
4. Send a browser-like UA, since the first sweep found that the default Python-urllib UA gets a 403.
5. For EU members, query `OECD.SDD.TPS,DSD_PRICES_COICOP2018@DF_PRICES_C2018_ALL,1.0` first and fall back to the 1999 flow. puremacro queries C2018 first for this reason, warning of EU series "stopping at 2025-12" ([puremacro](https://github.com/jalonso1979/puremacro/blob/main/puremacro/fetch/oecd_stes_panel.py)).

The same throttling covers monthly unemployment (`DSD_LFS@DF_IALFS_UNE_M`, where FREQ comes *last* in the key) and the CLI (`OECD.SDD.STES,DSD_STES@DF_CLI,4.1`, key `{AREA}.M.LI...AA...H`) ([vistamark oecd.ts](https://github.com/MRRVista/vistamark-ria-intel/blob/main/lib/intl-macro/oecd.ts)).

**World Bank `source=21` should be abandoned.** The GEM Commodities content now sits inside the "Commodity Prices – History and Projections" dataset, which the catalogue describes as annual ([World Bank Data Catalog](https://datacatalog.worldbank.org/search/dataset/0038238/commodity-prices-history-and-projections)). Live 2026 code states that "the Pink Sheet is not served by the World Bank indicators API" ([FinceptTerminal](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/fincept-qt/scripts/world_bank_commodity_data.py)). The stable route has six steps:

1. GET `https://www.worldbank.org/en/research/commodity-markets` with a UA.
2. Regex out `https://thedocs\.worldbank\.org/en/doc/[a-zA-Z0-9-]+/related/CMO-Historical-Data-Monthly\.xlsx` ([my-stock-screener](https://github.com/wudn9922/my-stock-screener/blob/main/scripts/build_world_assets.py)).
3. Fall back to the last known 2026 URL, `…/74e8be41ceb20fa0da750cda2f6b9e4e-0050012026/related/CMO-Historical-Data-Monthly.xlsx`. The doc id "rotates each release" ([FarmKonnect](https://github.com/abduljamil/FarmKonnect/blob/main/ml/training/collectors/fetch_worldbank.py)).
4. Read sheet "Monthly Prices" with no header.
5. Locate the row containing `CRUDE_BRENT`, and keep rows matching `^\d{4}M\d{2}$`.
6. Null out `..` values.

The old API codes map as follows: PNGASEU→`NGAS_EUR`, PNGASJP→`NGAS_JP`, PCOALAU→`COAL_AUS`, PALUM→`ALUMINUM`, PNICK→`NICKEL`, PZINC→`Zinc`, PIORECR→`IRON_ORE`, PUREA→`UREA_EE_BULK` and PDAP→`DAP`. Match case-insensitively, because the workbook mixes cases ([ASADO](https://github.com/ArjunDivecha/ASADO/blob/main/scripts/collect_wb_commodity_prices.py)). Palm oil's code is unconfirmed.

**Eurostat's calendar moved.** The ICS feed is now `https://ec.europa.eu/eurostat/o/calendars/eventsIcal?theme=0&category=0`; parse VEVENTs and keep `X-CATEGORY: Data release` ([ondata](https://github.com/ondata/opensdmx/blob/main/scripts/eurostat-rss/README.md)). The JSON fallback is `…/o/calendars/eventsJson?theme=0&category=0&start=2026-10-01T00:00:00%2B01:00&end=2026-12-01T00:00:00%2B01:00&timeZone=Europe%2FLuxembourg`. The flash-HICP calendar was retrieved from it on 11 October 2026 ([project-midas](https://github.com/chris-cheshire/project-midas-mk7/blob/main/midas/data/calendar/ea_hicp_flash.txt)). Its event times are UTC ([market-watch](https://github.com/akicestmoi/market-watch/blob/main/docs/DATA_SOURCES.md)). The numeric theme and category ids, other than 0 for all, are unconfirmed.

**Free official credit-spread series barely exist, so compute them.** ICE BofA OAS reaches FRED only under licence. The usable inputs are RBA F3 corporate yields, an ECB IFI daily euro-area corporate bond series whose meaning (spread or yield) is unconfirmed ([ECB IFI](https://data.ecb.europa.eu/data/datasets/IFI/IFI.D.U2.BC.4D.M040.ZZ.Z5.EUR)), and the government curves above as the risk-free leg. A licence-clean spread panel can then be computed in-house: DMO Nigeria Eurobond yield minus the matched-maturity Treasury par yield, RBA F3 minus F2, and ECB IRS 10Y minus the Bundesbank 10Y. Store derived values separately so the ESCB "do not modify" condition holds for the source series.

**Central-bank calendars remain a curation job.** No major central bank publishes an official ICS or JSON calendar that could be confirmed. The recommended design builds on the first report. Keep a versioned `cb_calendar` table (bank, start, end, decision time, timezone, projections flag, source URL, status). Seed it yearly from official pages. Run a weekly per-bank parser that alerts on any diff. Emit the platform's own ICS from the table.

## Equities need a vendor licence, while filings and fundamentals are free

**No exchange EOD source checked gives free commercial redistribution rights, and several tightened terms recently.**

- **Deutsche Börse:** its AWS Public Data Set is no longer maintained ([AWS registry](https://registry.opendata.aws/deutsche-boerse-pds/)), and EODHD announced it became an official Deutsche Börse distributor ([EODHD](https://eodhd.com/financial-apis-blog/eodhd-becomes-official-deutsche-borse-market-data-distributor)).
- **NSE India:** its policy says market data accessed for commercial purposes "shall be provided by NSE Data at a price approved by its Board" ([NSE](https://www.nseindia.com/static/market-data/nse-data-policy)).
- **JPX:** data received from an information vendor may not be redistributed ([JPX](https://www.jpx.co.jp/english/markets/paid-info-equities/realtime/01.html)).
- **CME:** EOD now falls under delayed licences at **$304/month** ([WatersTechnology](https://www.waterstechnology.com/data-management/7952957/cme-rankles-market-data-users-with-licensing-changes)).

The cheapest legal path for global prices is EODHD's bulk endpoint. Each exchange-wide `eod-bulk-last-day/{EX}` call costs 100 API calls, so seven or eight exchanges cost about 800 calls a day ([EODHD forum](https://forum.eodhd.com/t/what-are-the-most-economical-api-calls-to-download-the-last-known-eod-data/974)). That fits the $19.99 EOD All World plan's 100k calls/day, but **"commercial use requires the Startups & Enterprise plan"** ([apis.io](https://apis.io/plans/eodhd/eodhd-plans-pricing/)). The binding cost is the display licence, not API volume. Nasdaq Trader's symbol files (`nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt`, `otherlisted.txt`) are a free way to widen the US universe beyond 64 large caps, though they carry no prices and their terms were not found ([Nasdaq Trader](https://nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs)). **No free, legal source of index weights exists.** Wikipedia constituent lists are CC BY-SA, which imposes share-alike on any adapted list. Crypto free tiers are not commercial: CoinGecko Demo requires attribution and commercial use starts at Analyst ([CoinGecko](https://www.coingecko.com/en/api/pricing)), and CMC Basic is "personal use… No data redistribution permitted" ([CMC](https://coinmarketcap.com/api/pricing)). The existing EODHD and FMP crypto coverage, under their commercial terms, is the simpler route.

**EDGAR also works as a free corporate-events engine**, a facet the first report did not cover. The parsing details below rest on prior knowledge of the schemas and must be tested before use. The daily index lists Form 4, 8-K, S-1/F-1, 424B4 and Schedule 13D/G filings; filter by form type and parse each filing. The SEC's quarterly Insider Transactions Data Sets gained a Rule 10b5-1 flag (`AFF10B5ONE`) in July 2025 and suit backfill ([SEC](https://www.sec.gov/dera/data/form-345)). Five products follow:

- an insider-activity panel from Form 4 transaction codes (P/S/A/M/F);
- an events timeline keyed on 8-K item codes, with 2.02 as earnings, 5.02 for officer changes and 4.02 for restatements;
- an activist alert from 13D filings;
- an IPO calendar from the S-1 → 424B4 sequence;
- keyword alerts ("going concern", "material weakness") through the undocumented EFTS search.

**No free, licensed, forward earnings calendar exists.** Nasdaq.com's JSON calendar is unauthenticated, but its site terms bar commercial reuse ([nasdaq-public-api](https://socket.dev/pypi/package/nasdaq-public-api)). The legal workaround is to estimate "same fiscal quarter last year ± 7 days" from EDGAR history, mark it estimated, and upgrade it when an 8-K announces the date. The other option is a licensed calendar such as EODHD's ([EODHD calendar](https://eodhd.com/financial-apis/calendar-upcoming-earnings-ipos-and-splits)).

Market-structure data is mostly red. FINRA offers a **$0 Public API credential** covering Consolidated Short Interest and Reg SHO Daily ([FINRA fees](https://developer.finra.org/fees/public)), but its catalogue describes the short-sale data as **free for non-commercial use** ([FINRA](https://www.finra.org/finra-data/browse-catalog/short-sale-volume)). Commercial display needs FINRA's written confirmation or a licence. Cboe's DataShop says external redistribution of its index feed, including VIX, is "strictly prohibited" ([Cboe MDX](https://cdn.cboe.com/resources/us/indices/MDXCustomerAgreementMDI.pdf)). Sanctions lists, by contrast, are green and changed this year. **Since 28 Jan 2026 the FCDO UK Sanctions List is the only UK designations list**, so systems must key on the UKSL "Unique ID" instead of the OFSI Group ID ([GOV.UK](https://www.gov.uk/guidance/moving-to-a-single-list-for-uk-sanctions-designations-28-january-2026)). OFAC serves `sanctionslistservice.ofac.treas.gov/api/PublicationPreview/exports/SDN_ENHANCED.XML` ([OFAC SLS](https://sanctionslist.ofac.treas.gov/Home/static/sdn.html)). Ingesting these primary lists directly avoids OpenSanctions' commercial fee.

## Private markets gain a daily fund feed from Form D and ADV

The first report found free private-round data only where governments compel disclosure. The deeper sweep confirms that position and adds the fund side, which the first report covered only via Form ADV in outline.

**Form D is a free daily "new funds raising" feed.** Each Form D's `primary_doc.xml` carries `industryGroupType = "Pooled Investment Fund"` and an `investmentFundInfo` block with `investmentFundType`, which takes values such as "Hedge Fund", "Private Equity Fund" or "Venture Capital Fund", plus `is40Act` ([edgartools test data](https://github.com/dgunning/edgartools/blob/main/data/sgml/0002002260-24-000001.nc); [sec-api](https://github.com/SEC-API-io/sec-api-node/blob/master/README.md)). The platform already ingests Form D from the daily index. Filtering new `D` filings (not `D/A`) on that group gives roughly **160 new pooled-fund filings per business day**. That figure is arithmetic on a third-party count of 9,918 first-time funds in Q1 2026 ([Angel Investors Network](https://angelinvestorsnetwork.com/market-analysis/emerging-manager-fund-formation-2026-form-d-data)). The SEC's quarterly Form D Data Sets serve as backfill ([SEC](https://www.sec.gov/dera/data/form-d)). The manager name has no field of its own, so derive it from `relatedPersonsList`.

**Form ADV comes as two different free products, and only the old one has private funds.** The daily IAPD feed, `reports.adviserinfo.sec.gov/reports/CompilationReports/IA_FIRM_SEC_Feed_MM_DD_YYYY.xml.gz`, covered 23,638 firms (17,050 registered plus 6,588 exempt reporting advisers) as of July 2026 ([getfunded](https://github.com/Morton-Labs-AI/getfunded/blob/main/corpus/src/funderdb/sources/sec_adv.py)). The server keeps only about 7 days of files, and the feed has "no element [that] begins with `Sch`", so it carries **no Schedule D** ([HusshOne](https://github.com/hushh-labs/HusshOne/blob/main/services/ria-identity-api/docs/DATA-INVENTORY.md)). The fund-level table `IA_Schedule_D_7B1.csv` is in the FOIA archive `sec.gov/files/adv-filing-data-20111105-20241231-part2.zip`. It lists one row per fund with type, gross asset value and beneficial owners, but **ends 31 Dec 2024**; later data moved to IAPD ([SEC Form ADV Data](https://www.sec.gov/foia-services/frequently-requested-documents/form-adv-data)). The build is therefore a daily snapshot of the compilation feed, a one-off 7.B.1 backfill and per-firm ADV PDFs for 2025 onward.

## X ingestion is viable in late 2026 only as a paid, alert-only API layer

**X is viable for a commercial app in late 2026 through the official pay-per-use API, and only as a trigger that points to primary sources.** Pay-per-use became the default around 6 Feb 2026, with no free tier for new developers ([roboin](https://roboin.io/article/en/2026/02/08/x-transitions-api-to-pay-per-use-model-ending-free-plan/)). The rates are **$0.005 per post read, $0.010 per user read and $0.001 per owned read**, deduplicated within a 24-hour UTC window. X calls that deduplication a "soft guarantee" ([X pricing](https://docs.x.com/x-api/getting-started/pricing)). The monthly cap is still disputed, at 2M or 3M post reads before Enterprise ([Outstand](https://www.outstand.so/blog/x-api-pricing)).

The new efficiency finding concerns List timelines. `GET /2/lists/:id/tweets` allows 900 requests per 15 minutes, though older docs say it returns only a list's latest 800 posts ([X lists](https://developer.x.com/en/docs/x-api/lists/list-tweets)). Billing is per post read, not per call. So polling roughly 200 official accounts with `since_id` costs about 18,000 post reads (~$90) plus about 6,000 user reads (~$60) a month, **roughly $100–200 in all**. That is the deeper note's calculation, and it is lower than the first report's estimate.

**The terms constrain the design more than price does.** The Developer Agreement bars using X content to train or fine-tune foundation models ([KnowTechie](https://knowtechie.com/x-developer-agreement-bans-ai-training)). The display rules require posts to appear unmodified, with edit history, and with name, handle and logo alongside any images; X "strongly encourages" embeds ([X display requirements](https://docs.x.com/developer-terms/display-requirements.md)). The legal climate for scrapers has not improved enough to rely on. In *X v. Bright Data*, X's scraping claims were held copyright-preempted in 2024. **Bright Data's antitrust counterclaims then survived X's motion to dismiss** ([StartupHub](https://www.startuphub.ai/news/federal-court-upholds-bright-datas-antitrust-claims-against-x); [Eric Goldman](https://blog.ericgoldman.org/archives/2025/01/catching-up-on-the-heavyweight-scraping-battle-between-x-and-bright-data-guest-blog-post.htm)). The case is unresolved and does nothing for a company holding an X developer account.

The architecture follows from those terms. Store only the post ID, author, timestamp and URL. Classify the post with rules, resolve the linked primary document, extract the figure from that document, compare it with the post, and mark the result `verified_primary`, `pending` or `review`. Any LLM classification should run on the primary document, never on X text. Handle evidence is thin. **Only @cenbank, @CBKKenya, @nigerianstat and @ngxgrp were confirmed, and only through secondary pages** ([LunarCrush](https://lunarcrush.ai/html/creator/twitter::16182044/posts); [speakrj](https://www.speakrj.com/audit/report/CBKKenya/twitter); [BusinessPost NG](https://businesspost.ng/?p=81317)). Every other handle must be checked against the institution's own footer before it goes on the List. CBN itself tells the public to verify communications through its website ([AllAfrica](https://allafrica.com/stories/202604220078.html)). That makes X a source of minutes saved on unscheduled central-bank decisions and early funding-round mentions. It adds nothing on scheduled CPI or GDP releases.

The free complements are better than expected for Western institutions and thin for African ones. The ECB has been on Bluesky since 13 Jan 2025 ([RTÉ](https://www.rte.ie/news/business/2025/0113/1490550-european-central-bank-joins-bluesky-rival-to-musks-x)), and the Fed posts as the domain-verified @federalreserve.gov ([mirror](https://oauth.lightnews.app/bsky/federalreserve.gov)). Bluesky's Jetstream WebSocket filters server-side by `wantedDids` with no key ([Parker Higgins](https://parkerhiggins.net/2025/04/realtime-bluesky-events-jetstream-for-helping-friendly-bot/)), so a watchlist stream costs nothing. Threads keyword search needs an approved permission ([Meta](https://developers.facebook.com/documentation/threads/keyword-search)). **Telegram's 2026 terms prohibit scraping by anyone and explicitly target AI training** ([Open Terms Archive](https://opentermsarchive.org/en/memos/telegram-prohibits-collecting-data-for-ai-use/)). Reddit's Data API is free only for approved non-commercial use ([apiserpent](https://apiserpent.com/blog/reddit-api-comparison-2026)). Substack, YouTube and institution RSS feeds are the cheapest alert inputs of all.

## Conclusion

The second sweep changes where the engineering effort should go. The first report concluded that licence hygiene, not more APIs, was the bottleneck. That still holds, but the deeper evidence shows that **the clean official layer is much wider and more API-shaped than assumed**. The G10 curves, the G20 statistics offices, EU gas and UK power, US positioning and SEC filings are all keyless or free-key, and most carry explicit commercial-reuse terms. The platform's competitive edge therefore shifts away from data acquisition towards provenance infrastructure. That means a per-host rate limiter with a contact User-Agent, which alone would have prevented two of the five current failures. It also means per-series `licence` and `attribution` fields rendered in the UI, "modified data" flags for computed values, and a verification log populated from Vercel. Built once, this infrastructure serves every row in the ranked plan.

The paid frontier is also clearer and cheaper to enter than it looked. Display rights for global equities (an EODHD commercial plan), Nigerian equities (an NGX EOD tier), Nigerian money markets (FMDQ) and real-time social alerts (about $100–200/month of X credits) are four bounded purchases. Each can be justified by usage rather than bought up front. The open risk is legal, not technical. A dozen useful sources sit in amber because their terms pages could not be read from the sandbox, among them GIE, ENTSO-E prices, ICE COT, RBA Section 5, SARB and the Fed nowcasts. The permission emails in rank 3 are therefore the highest-leverage hour of work in this plan.
